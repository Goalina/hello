## 一、基本信息

| 项目 | 内容 |
|------|------|
| **故障标题** | triton-ascend CI 资源持续调度失败 |
| **故障时间** | 2026年7月28日 22:30 — 23:55 |
| **影响范围** | triton-ascend A3 CI 流水线 |
| **发现方式** | A3 CI 任务持续等待，无法调度到可用节点 |

## 二、故障现象

- 22:30 后 triton-ascend 的 A3 CI 流水线任务处于等待状态，无法被调度
- 所有依赖 CI 资源的提交验证、PR 合入检测等流程均被阻塞
- 开发者提交代码后无法获得 CI 反馈，影响正常开发节奏

### 时间线

| 时间 | 事件 |
|------|------|
| 7月28日 22:30 | 定时任务触发，8台 A3 节点被打上污点 |
| 7月28日 22:30 — 23:55 | CI 资源持续不可用，流水线受阻 |
| 7月28日 23:55 | 故障手动恢复 |

---

## 三、故障影响

**CI 服务不可用**：A3 triton-ascend CI 堵塞无法运行，影响以下 PR：

- [PR #1274](https://github.com/triton-lang/triton-ascend/pull/1274)

---

## 四、根因分析

### 4.1 根本原因（五问法）

```
为什么无法调度成功？
  └─ 因为集群内大部分机器有污点（Taint）
       └─ 为什么集群大部分机器有污点？
            └─ 因为在该集群内测试部署了定时任务污点，以满足多机用例的需要
```

### 4.2 事件链路

```
定时任务（CronJob）每晚 22:30 触发
  → 对 8 台 A3 节点打上 Taint
    → triton-ascend CI Pod 不满足 Taint 容忍条件，无法调度
      → 仅剩 3 台可用节点，资源不足
        → CI 任务持续等待
```

---

## 五、应急措施

> 23:55 手动移除被打上污点节点的 Taint，恢复 CI 调度能力
